## Premortem

Six months from now the plan has failed. Three ways it could happen:

1. The first CI run of the implementation fails. The branch now contains PR #85, whose guard `scripts/check_ci_test_targets.py` rejects a bare `#[ignore]`, and tasks 5.3 to 5.5 add three. If the implementer drops the attribute instead, the plan's checklist command runs with `-- --ignored`, skips the three new tests, and reports 0 failures. Routed to Feasibility, `[HIDDEN_DEPENDENCY]`.
2. A Python user binds a historical timestamp through the ADBC driver manager. Before this plan it bound a wrong instant, because the FFI binding converts to nanoseconds and overflows before 1677-09-21. This plan fixes that by accident, but no release note, scenario, or test names the fix, so the user never re-checks the stored data, and nothing pins the fix. Routed to Requirement Quality, `[COMPLETENESS_GAP]`.
3. A later change adds a new import format and writes its own date formatter, because `specs/architecture.md` still describes `types` as a type mapper only. The rule is in two places again, the same drift that caused issue #84. Routed to Design Depth, `[ARCHITECTURE_DRIFT]`.

#### [INFORMATION_LEAKAGE] ADVISORY
- Location: plan.md tasks 4.2 and 4.4; decision-log.md entry [3]
- Issue: All three callers, `format_timestamp` in `src/import/arrow.rs`, `format_timestamp` in `src/import/parquet.rs`, and the Timestamp arm of `arrow_value_to_parameter`, call `timestamp_to_micros(unit, value)` and then `format_timestamp_micros(micros)`. No caller uses either function alone. The decision to reduce a value to microseconds before formatting therefore sits in three callers. Exasol TIMESTAMP holds up to nine fractional digits (`type-mapping/boundaries-and-validation` Background), so a later change that keeps nanoseconds edits all three.
- Fix: In task 4.2, make the public interface one function, `format_arrow_timestamp(unit: &TimeUnit, value: i64) -> Result<String, String>`, which calls `timestamp_to_micros` and `format_timestamp_micros`. Keep those two private and keep the tests of task 4.1 on them. Update tasks 4.3 and 4.4, entry [3], and § Dead Code Removal to the new name.
