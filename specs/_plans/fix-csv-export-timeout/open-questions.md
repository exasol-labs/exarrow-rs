# Open Questions: fix-csv-export-timeout

speq-plan-pr could not complete this plan without human input. What's done so far is committed on this branch. Reply inline on the PR, or resume with `/speq:plan fix-csv-export-timeout` locally, or re-run `/speq:plan-pr fix-csv-export-timeout` after commenting.

Both questions below are mechanical fixes with prescribed text — they surfaced because a fix approved in the previous round (adopting `Cell<bool>`, and adopting the `is_closed()` change) introduced a new bug each, caught only by this round's adversarial review. Full findings: `specs/_plans/fix-csv-export-timeout/review/round-2.md`.

- [ ] **`[NFR_IGNORED]` BLOCKER — `Cell<bool>` makes exports `!Send`, breaking `tokio::spawn`.** Task 3.1 uses `std::cell::Cell<bool>` for the progress flag that tracks whether the SQL response was read. `&Cell<bool>` is not `Send` (verified: `rustc` rejects a future that holds it across an await point), so every public `Connection::export_*` method becomes `!Send`. Nothing in-repo detects it, no test spawns an export, but a caller who does `tokio::spawn(async move { conn.export_csv_to_file(...).await })` — the normal way to run a multi-minute export in the background — stops compiling. Prescribed fix: swap `Cell<bool>` for `std::sync::atomic::AtomicBool` (`Send`, no thread crossing needed, `Ordering::Relaxed` is enough), and add a `fn assert_send<T: Send>(_: T) {}` test pinning the guarantee.

- [ ] **`[UNSTATED_ASSUMPTION]` BLOCKER — the mock test double panics after the `is_closed()` change.** A prior round adopted a fix making `Connection::is_closed()` also check `transport.is_connected()`. Task 2.3 claims two existing unit tests "still hold" after that change, but both use `MockTransport` (a `mockall::mock!` double), which panics on any call with no expectation set — and no test currently sets an expectation for `is_connected()`. Both tests panic once this lands, and `cargo test --lib` goes red at that task boundary. Prescribed fix: add `transport.expect_is_connected().returning(|| true);` to both mocks, plus a new test case where the mock returns `false` to assert `is_closed()` picks it up.

Reply "apply both fixes" to accept them as written, or say if either changes something you'd rather keep as-is (for example, a different atomic ordering, or a different way to unblock the mock tests).
